One group could work on the public website. Another could work on authentication. Another could work on the dashboard. Another could work on projects and events. Another could work on reusable components and supporting functionality.
This structure allows many participants to contribute at the same time while still giving everyone an individual responsibility.
Throughout the exercise, participants will practice the complete collaboration cycle. They will clone the repository, create branches, work on tasks, make commits, push branches, open Pull Requests, review other developers' code, respond to feedback, synchronize their branches, resolve merge conflicts, and merge completed work into the shared project.
The final result should be more than just a working website. The class should also have a shared GitHub history showing how many developers contributed to one project.
The purpose of this activity is to move from learning Git commands individually to understanding Git as a collaboration system. In a real software development environment, developers rarely work completely alone. They work with other developers, designers, testers, project managers, and other contributors. They need to understand how their changes affect the rest of the project and how to safely bring their work together.
By the end of the practice, every participant should have experienced both sides of collaboration: being a developer who submits work and being a teammate who reviews someone else's work.
The final workflow we are practicing is:
Choose a task → Create a branch → Develop → Commit → Push → Open Pull Request → Review → Discuss → Make changes → Update Pull Request → Approve → Merge → Synchronize → Continue collaborating.
The project can continue to grow as more participants contribute. If the class has 25 participants, everyone can have an individual task. If the class has 30, 40, or more participants, the same workflow can be expanded by creating more teams, features, components, issues, and review groups.
The objective is to simulate a real collaborative development environment where many developers are contributing to one shared codebase while using Git and GitHub to keep the work organized, traceable, and reviewable.
